# 데이터 조합 분석_v1.xlsx

엑셀 작업 화면처럼 보이는 2~4인 루미큐브입니다. 실제 루미큐브 규칙 검증은 항상 서버에서 수행하며, 상대의 손패와 덱 순서는 브라우저에 보내지지 않습니다.

## 이용 방식

- **AI 모드**: 개인 분석을 선택하면 AI와 즉시 시작합니다.
- **초대 대전**: 공유 분석을 만들 때 `초대 전용`을 고르면 6자리 코드나 링크를 받은 사람만 입장할 수 있습니다.
- **공개 대전**: `공개 대기실`을 고르면 홈의 공개 분석 대기 목록에 표시됩니다. 시작 전이고 빈자리가 있을 때만 입장할 수 있습니다.

## 로컬 실행

```powershell
npm start
```

브라우저에서 `http://localhost:4173`을 엽니다. 로컬 개발 서버는 메모리 저장소와 즉시 타이머를 사용하므로, 서버를 다시 시작하면 로컬 방은 사라집니다.

## Vercel 정식 운영 구조

| 역할 | 구성 |
| --- | --- |
| 화면과 API | Vercel (`public/`, `api/`) |
| 방·손패·덱·턴 상태 | Upstash Redis |
| 턴 만료와 AI 차례 | Upstash QStash |
| 브라우저 갱신 | 짧은 상태 동기화 폴링 |

Vercel 배포에서는 방 전체를 Redis에 저장하고, 방별 Redis 잠금과 revision 비교 저장으로 동시 입장·동시 제출의 덮어쓰기를 막습니다. QStash 작업에는 예상 시각과 방 코드가 들어가므로 늦게 도착한 예전 작업은 현재 턴과 일치하지 않으면 무시됩니다. 공개 대기실에는 초대 전용·AI·시작된·가득 찬 방이 절대 노출되지 않습니다.

### 최초 설정

1. Vercel에서 이 GitHub 저장소를 새 프로젝트로 연결합니다.
2. Vercel Marketplace에서 **Upstash Redis**를 설치해 프로젝트에 연결합니다. `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`이 자동으로 추가됩니다.
3. Upstash QStash에서 토큰과 두 서명 키를 만들고 Vercel 환경 변수에 추가합니다.
4. `.env.example`의 `DCA_APP_ORIGIN`에 실제 Vercel 주소를, `DCA_SESSION_SECRET`에는 긴 무작위 값을 넣습니다.
5. Vercel의 Production 환경에 위 변수를 모두 저장한 뒤 `main` 브랜치를 배포합니다.
6. 배포 후 `https://<도메인>/api/health`에서 Redis·예약 작업·세션 설정이 모두 준비됐는지 확인합니다.

환경 변수는 저장소에 절대 커밋하지 않습니다. 자세한 항목은 [.env.example](.env.example)을 참고하세요.

## 운영 보안과 데이터 보호

- 브라우저마다 HttpOnly 익명 세션 쿠키를 발급하고, Vercel API는 그 세션으로 방 권한을 판단합니다.
- 클라이언트가 전달하는 예전 `clientId` 값은 정식 운영 Vercel API에서 권한 판정에 사용하지 않습니다.
- 초대 코드가 없는 방은 공개 목록에 나타나지 않으며, 비참가자는 입장 가능한 대기실의 최소 정보만 확인할 수 있습니다.
- 세션 발급·방 조회·입장에는 짧은 보관 기간의 IP 해시 기반 요청 제한을 함께 적용합니다.
- 모든 이동·조합·첫 등록 30점·조커 대체값·턴 시간은 서버가 다시 검증합니다.
- 방은 기본 36시간, 종료된 방은 기본 4시간 뒤 자동 만료됩니다. 필요하면 환경 변수로 조정할 수 있습니다.

## 포함된 규칙

- 106 타일(4색 × 1~13 × 2장 + 조커 2장), 각 14장 배분
- 같은 숫자의 서로 다른 색 3~4장 / 같은 색 연속 숫자 3장 이상
- 첫 등록은 본인 손패만으로 30점 이상
- 등록 후 보드 재배치 가능, 단 매 턴 손패 타일 1장 이상 제출
- 조커의 대체 숫자·색을 서버가 저장하고 모든 최종 조합을 검증
- 뽑기는 1장 후 턴 종료, 풀 소진 뒤 모두 패스하면 종료
- 시간 종료 시 초안은 되돌아가며, 편집 중이었다면 3장 / 아니면 1장을 자동으로 뽑음
